1. WHAT IS ROUTEVIEW
==============================================================================

RouteView is an intelligent public-transportation platform for Rwanda with
two offerings in one application:

  · URBAN — city buses in Kigali (routes R1–R4), live tracking on a map,
    journey planning, digital QR tickets for city trips.

  · INTERPROVINCIAL — long-distance buses from Nyabugogo to every Rwandan
    province (Musanze, Rubavu, Huye, Rwamagana, Rusizi, Nyagatare, etc.)
    operated by real companies (Volcano, Ritco, KBS, Trinity, Alpha, Omega,
    Jali, Star). Book online, get a QR e-ticket that can be printed and
    scanned once by the driver.

The platform also includes an AI assistant (Kinyarwanda + English) powered
by OpenRouter, a Python machine-learning model that predicts bus arrival
times, an operator/admin dashboard, and an AI-assisted place finder.

Data sources are clearly labelled:
  · Real coordinates and routes are demonstration data unless stated.
  · Vehicle positions marked "simulator" are simulated.
  · The ML model is trained on synthetic data (documented in ml/).

2. FEATURES
==============================================================================

Passenger:
  · Home page with live stats, route preview, service alerts.
  · Search stops, view route details, journey planner with fares.
  · Live map of every vehicle, route polylines, satellite toggle.
  · AI assistant (floating dock) in Kinyarwanda or English, tool-calling.
  · Find places nearby with AI chat + real OpenStreetMap POI data.
  · Book urban tickets with QR codes.
  · Book interprovincial tickets with a printable A4 QR e-ticket.
  · Digital tickets lock after one scan.

Operator / Administrator:
  · Separate staff login (/admin/login) with invite code for registration.
  · Fleet monitoring on the map.
  · Ticket validation (QR scan or manual code entry) for both urban and
    interprovincial tickets — one-time use enforced server-side.
  · Manage routes, stops, vehicles, service alerts, users.
  · Analytics: bookings per route, daily redemptions, revenue.
  · System status: DB, ML service, AI provider, live vehicle counts.

Infrastructure:
  · Built-in fleet simulator runs inside the backend — no extra process.
  · Real road geometry from OSRM for smooth vehicle movement.
  · ESP32/Wokwi firmware provided for real GPS devices.
  · REST API with JWT auth, role-based access, rate limiting.
  · MySQL schema with foreign keys, unique constraints, and safe concurrency.

==============================================================================
6. FIRST-TIME SETUP (STEP BY STEP)
==============================================================================

Follow these in order. Every command is PowerShell.

--- STEP 1: Put the project in place --------------------------------

Place the entire project folder at a path with no spaces. Recommended:
  C:\xampp1\htdocs\routeview_v1

Then open PowerShell and go to the root:
  cd C:\xampp1\htdocs\routeview_v1

--- STEP 2: Create the root .env file ------------------------------

Copy the template:
  Copy-Item .env.example .env

Open it in VS Code:
  code .env

Fill in the values you need. See section 7 for the full list.
The two you MUST set are:
  - DB_PASSWORD     (blank for a fresh XAMPP install)
  - OPENROUTER_API_KEY  (starts with sk-or-v1-)

Save and close.

--- STEP 3: Create the frontend env file ---------------------------

Copy the template:
  Copy-Item frontend\.env.local.example frontend\.env.local

Or create it manually with these two lines:
  NEXT_PUBLIC_API_URL=http://localhost:4000
  NEXT_PUBLIC_TILE_URL=https://{s}.tile.openstreetmap.org/{z}/{x}/{y}.png

If you changed the backend port (e.g. to 4001), update the URL here too.

--- STEP 4: Install backend dependencies ---------------------------

  cd backend
  npm install

Expected: "added ~190 packages". Takes 1–2 minutes.

Then go back to the root:
  cd ..

--- STEP 5: Install frontend dependencies --------------------------

  cd frontend
  npm install

Expected: "added ~350 packages". Takes 2–4 minutes. Next.js is heavy.

Then back to the root:
  cd ..

--- STEP 6: Install simulator dependencies -------------------------

  cd simulator
  npm init -y
  npm install dotenv jsonwebtoken
  cd ..

(You only need the simulator if you want an external process. The backend
has its own built-in one that starts automatically.)

--- STEP 7: Create the Python virtual environment ------------------

  cd ml
  python -m venv .venv
  .\.venv\Scripts\Activate.ps1

If PowerShell blocks the activate script:
  Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
Then run activate again.

Your prompt should now show (.venv).

--- STEP 8: Install Python dependencies ----------------------------

  python -m pip install --upgrade pip
  pip install -r requirements.txt

Takes 2–5 minutes. All packages have prebuilt Windows wheels.

--- STEP 9: Generate the synthetic dataset -------------------------

  python generate_dataset.py

Expected: "[generate_dataset] wrote 60000 rows -> ...".

--- STEP 10: Train the ML model ------------------------------------

  python train.py

Expected:
  [train]   linear  MAE=  xxx s
  [train]      gbr  MAE=   xx s
  [train]       rf  MAE=   xx s
  [train] best model: gbr (MAE xx s)
  [train] saved model + metrics

The winner is usually gbr. Either is fine.

--- STEP 11: Set up the database -----------------------------------

Start MySQL in XAMPP (green light).
Then from the backend folder:

  cd ..\backend
  npm run db:init

Expected: "[db:init] schema applied."

Now load the urban demo data:

  npm run seed

Expected: "[seed] demo data inserted."

Now create the interprovincial schema and seed:

  mysql -u root routeview < src\db\intercity_schema.sql
  npm run seed:intercity

Expected: "[ic-seed] 8 companies" and "[ic-seed] 50 route directions"
and "[ic-seed] ~4000 trips".

Verify in MySQL:
  mysql -u root -e "USE routeview; SHOW TABLES;"
Should show 15 urban tables + 6 intercity tables.

--- STEP 12: You are ready to run -------------------------------
See section 10.

  NEXT_PUBLIC_API_URL=http://localhost:4000
  NEXT_PUBLIC_TILE_URL=https://{s}.tile.openstreetmap.org/{z}/{x}/{y}.png

If you change the backend PORT above, change NEXT_PUBLIC_API_URL here too.

8. DATABASE SETUP
==============================================================================

The database is called routeview and lives in XAMPP's MySQL.

There are two schemas:
  · backend/src/db/schema.sql           — urban system (15 tables)
  · backend/src/db/intercity_schema.sql — interprovincial (6 tables)

URBAN SETUP
  cd backend
  npm run db:init
  npm run seed

INTERPROVINCIAL SETUP
  mysql -u root routeview < src\db\intercity_schema.sql
  npm run seed:intercity

That inserts:
  · 8 bus companies
  · 25 city/terminal definitions
  · ~50 route directions (Kigali↔each province, cross-province)
  · ~75 daily schedules
  · ~4,000 individual trips for the next 14 days

To RESET the database at any time:
  npm run db:init       (drops and recreates urban tables)
  npm run seed
  mysql -u root routeview < src\db\intercity_schema.sql
  npm run seed:intercity

To verify data:
  mysql -u root -e "USE routeview; SELECT COUNT(*) FROM stops;"
  mysql -u root -e "USE routeview; SELECT COUNT(*) FROM intercity_routes;"
  mysql -u root -e "USE routeview; SELECT COUNT(*) FROM intercity_trips;"

9. MACHINE LEARNING MODEL
==============================================================================

The arrival-time model is trained on a synthetic dataset.

TRAINING
  cd ml
  .\.venv\Scripts\Activate.ps1
  python generate_dataset.py
  python train.py

Produces:
  artifacts/dataset.csv          60,000 synthetic rows
  artifacts/arrival_model.joblib the trained pipeline
  artifacts/metrics.json         training metrics + disclaimer

The metrics describe fit to the synthetic generator, not real-world
accuracy. This is honest and documented in the metrics file.

SERVING
  uvicorn service:app --port 8000

Endpoints:
  GET  /health      — { ok, model_version, chosen }
  POST /predict     — takes features, returns { seconds, ... }

Features the model expects:
  route_id, hour_of_day, day_of_week, distance_remaining_m,
  recent_speed_kmh, remaining_stops, delay_indicator

The backend calls /predict from services/arrival.js. If the ML service
is down, the backend falls back to a physics estimate and labels it
"source: fallback". The app never breaks.

RETRAINING
  Replace artifacts/dataset.csv with real telemetry using the same
  seven columns, bump MODEL_VERSION inside train.py, rerun train.py,
  restart uvicorn. The backend picks up the new model on the next call.

12. AI ASSISTANT SETUP (OPENROUTER)
==============================================================================

1. Get an API key at https://openrouter.ai/keys
2. Paste it in .env:  OPENROUTER_API_KEY=sk-or-v1-...
3. Add credit at https://openrouter.ai/credits ($5 lasts thousands
   of messages on gpt-4o-mini or claude-3.5-haiku).
4. Pick a model that supports tool calling. In .env:
     OPENROUTER_MODEL=anthropic/claude-3.5-haiku
   or
     OPENROUTER_MODEL=openai/gpt-4o-mini
5. Restart the backend.

Verify:
  Invoke-RestMethod http://localhost:4000/health
  → ai_configured : True

If ai_configured is False:
  · Confirm the .env line has no quotes around the key.
  · Restart the backend (it reads .env only at startup).
  · Confirm config.js points to the correct .env path (it uses
    path.resolve(__dirname, '../../.env') so it always finds the
    root file regardless of working directory).

WHY THIS MATTERS
  The assistant uses OpenRouter for language understanding. It calls
  tools that query the real database. It never invents routes, fares,
  or live bus positions. If OpenRouter is unreachable, the app shows
  a clearly-labelled fallback message and everything else keeps working.

13. PHYSICAL GPS / ESP32 SETUP (OPTIONAL)
==============================================================================

The platform accepts real GPS positions from ESP32 devices. Both the
built-in simulator and real devices write to the same endpoint and the
same table, so they can coexist.

ENDPOINT
  POST /api/vehicles/ingest
  Requires operator or admin JWT.

PAYLOAD
  {
    "vehicle_id": 1,
    "route_id": 1,
    "lat": -1.9441,
    "lng": 30.0619,
    "speed_kmh": 32.5,
    "heading_deg": 45,
    "source": "gps"
  }

SETUP
  1. Open firmware/esp32_gps/esp32_gps.ino in Arduino IDE or the
     Wokwi editor (https://wokwi.com).
  2. Set WIFI_SSID and WIFI_PASS.
  3. Set API_URL to your machine's LAN IP, e.g.
     http://192.168.1.100:4000/api/vehicles/ingest
  4. Generate an operator JWT:
       cd backend
       node -e "console.log(require('jsonwebtoken').sign({id:2,email:'operator@routeview.rw',role:'operator'}, 'your-jwt-secret', {expiresIn:'7d'}))"
  5. Paste the token into OPERATOR_TOKEN in the .ino file.
  6. Flash. Positions will arrive on the map as blue markers.

The map distinguishes:
  · Blue  → GPS feed (source: "gps")
  · Amber → Simulated feed (source: "simulator")

14. TROUBLESHOOTING
==============================================================================

ERROR: EADDRINUSE (address already in use :::PORT)
  Something is holding the port. Two options:
   A. Change PORT in .env to 4001 and NEXT_PUBLIC_API_URL in
      frontend/.env.local to match. Restart both.
   B. Kill the process:
        Get-Process node | Stop-Process -Force
        netstat -ano | findstr :4000
        taskkill /F /PID <pid>

ERROR: Cannot find module 'xyz'
  Run npm install in the folder that imports it. If the error mentions
  a specific service (e.g. fleetSimulator.js), the file was not
  created — copy it from the documentation.

ERROR: 'Identifier XYZ has already been declared'
  Duplicate import. Open the file, find the repeated line at the top,
  delete one. Rule: all imports at the top, no duplicates.

ERROR: AuthProvider missing
  app/layout.tsx is not wrapping children in <AuthProvider>. See
  section 4 for the folder structure; ensure the root layout file
  contains <AuthProvider>.

ERROR: ai_configured : False after setting the key
  · Check the .env line has no quotes.
  · Restart the backend (Ctrl+C, npm run dev).
  · Confirm config.js loads from '../../.env'.

ERROR: openrouter_400
  The chosen model does not support tool calling. Change
  OPENROUTER_MODEL in .env to anthropic/claude-3.5-haiku or
  openai/gpt-4o-mini. Restart the backend.

ERROR: openrouter_401 / 402
  401 = invalid key. Check the OpenRouter dashboard.
  402 = no credit. Add $5 at openrouter.ai/credits.

ERROR: "Failed to fetch" in the browser
  The backend is not reachable.
   · Confirm the backend is running (Invoke-RestMethod .../health).
   · Confirm frontend/.env.local has the correct API URL and that
     the frontend was restarted AFTER editing it.
   · If you changed the backend port, update both files.

ERROR: Map shows "API KEY REQUIRED"
  You are using CARTO tiles that need a key. Confirm the tile URL is
  https://{s}.tile.openstreetmap.org/{z}/{x}/{y}.png in MiniFleetMap.tsx
  and LiveMap.tsx. Restart the frontend.

ERROR: 0 buses on the map
  The built-in simulator did not start. Check the backend terminal:
   · Should print "[sim] fleet simulator started — 12 vehicles".
   · If not, confirm SIMULATE_VEHICLES=true in .env.
   · Confirm there are routes with at least 2 stops:
       mysql -u root -e "USE routeview; SELECT route_id, COUNT(*) FROM route_stops GROUP BY route_id;"

ERROR: Tickets search returns nothing
  The intercity schema or seed has not been applied. Run:
    mysql -u root routeview < backend\src\db\intercity_schema.sql
    cd backend && npm run seed:intercity

ERROR: QR scan says "already_used" on first scan
  That means the ticket was already used in a previous test. Create
  a new booking or reset the intercity tables.

ERROR: python -m venv fails
  Python is not on PATH. Reinstall Python from python.org and check
  "Add python.exe to PATH" during setup.

ERROR: pip install fails on scipy
  No prebuilt wheel found. Force wheel-only:
    pip install --only-binary=:all: -r requirements.txt

ERROR: Model training is slow
  On 8 GB RAM, edit ml/generate_dataset.py: change N = 60_000 to
  N = 20_000. Retrain. Same quality, half the time.
